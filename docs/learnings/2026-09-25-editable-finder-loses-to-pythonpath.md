fact: The setuptools editable install (`pip install -e .`, `.pth` + `_EditableFinder`) is APPENDED to `sys.meta_path`, after `PathFinder`. So any `kvt`/`scripts` found on `sys.path` first (`PYTHONPATH`, or the cwd that `python -m pytest` inserts) shadows the installed repo, and the editable finder only answers when nothing on the path does. This is what makes "test a historical commit in a detached worktree with `PYTHONPATH=<worktree>`" honest: the worktree's modules win, as the ImportError path in the out-of-order-commits entry shows. The converse also holds: the finder's package map (`MAPPING`) is baked at install time, so a new top-level package or a console script does not exist until the editable install is re-run.
