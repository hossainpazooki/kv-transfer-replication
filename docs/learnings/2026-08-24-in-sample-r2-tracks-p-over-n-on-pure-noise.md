fact: For a centered least-squares fit on data with NO signal whatsoever, in-sample R^2 tracks the ratio p/n (features over training rows) almost exactly, so an in-sample R^2 is only informative when p/n is far below the value being reported. Measured on pure Gaussian noise: p/n = 0.050 -> in-sample R^2 0.0514; 0.100 -> 0.0969; 0.160 -> 0.1597; 0.800 -> 0.8016, with held-out R^2 negative in every case (-0.052, -0.109, -0.193, -4.017). Practical consequence for this repo: at 50 calibration sequences the k=8 mapper has p = 8*8*128 = 8192 against n = 10240 train tokens, i.e. p/n = 0.800 exactly — so its measured in-sample R^2 of 0.9607 sits barely above what pure noise would produce, and carries almost no evidence. Any paper or report quoting in-sample R^2 without stating p/n should be read with this substitution in mind.
