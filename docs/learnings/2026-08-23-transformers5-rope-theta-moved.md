fact: In transformers 5.x the attribute `config.rope_theta` DOES NOT EXIST on Qwen3 configs — the value moved into `config.rope_parameters["rope_theta"]`. Code written against 4.x that reads `config.rope_theta` either raises or, worse, silently substitutes a default if written defensively. This is uniquely dangerous for RoPE strip/re-apply work because a consistently-wrong theta CANCELS in a round trip: strip-then-reapply still returns the original tensor, so a self-mapping / identity test passes and the error only surfaces as degraded cross-model quality with no failing test anywhere. Accessors for this value must raise rather than default. Note `Qwen3Config(rope_theta=1e4)` still ACCEPTS the kwarg (it is absorbed into `rope_parameters`), so constructor-based test fixtures keep working — only reading it back changed, which is what makes the break easy to miss.
basis: `.venv/Scripts/python.exe -c "from transformers import AutoConfig; c=AutoConfig.from_pretrained('Qwen/Qwen3-0.6B'); print('hasattr rope_theta:', hasattr(c,'rope_theta'), '| rope_parameters:', c.rope_parameters)"` printed "hasattr rope_theta: False | rope_parameters: {'rope_theta': 1000000, 'rope_type': 'default'}" against transformers 5.15.1 / torch 2.13.0+cpu.
